## 최우선 원칙: 사람과 프로젝트가 주인공
> 이 사이트의 중점은 **이력서 정보가 아니라 "박영우라는 사람"과 "그가 만든 프로젝트"를 소개하는 것**(본인 재강조). 경력 섹션은 **보조적이고 컴팩트하게** — 화면 비중·스크롤 길이 모두 Narrative와 Projects보다 작게.

## 원칙
- **와이드 & 여백**: 넓은 컨테이너, 큰 섹션 간격, 요소 수 최소화.
- **풀블리드 히어로**: 전면 이미지/영상 + 대형 타이포 오버레이(가독성용 그라디언트 스크림).
- **모던·클린·절제**: 컬러는 뉴트럴 베이스 + 프로젝트별 accentColor만 포인트.
- **모션**: 스크롤 리빌, 패럴럭스(약하게), 숫자 카운트업, 호버 마이크로 인터랙션. `prefers-reduced-motion` 존중.
- **타이포**: Pretendard Variable 유지(`css/style.css`), `word-break: keep-all` 유지.
- 라이트/다크 테마 토글 유지, 모바일 320px 대응, Lighthouse 성능·접근성 90+ 목표, 이미지 lazy-load·WebP/AVIF.

## 페이지 구조
1. **Hero** — 확정 카피: **"흩어진 기록을 / 데이터로 연결하여, / 인사이트를 비지니스로"** + 영문 서브카피: *"Connecting scattered records into data, and turning insight into business."* + 풀블리드 비주얼 + 스크롤 유도.
   - 이미지: **인물/초상 금지**. 카피에 맞는 **직접 생성 이미지** 권장 — 흩어진 기록(사진·지도 핀·일정·영수증 조각)이 선/노드로 연결되어 데이터·인사이트로 수렴하는 장면. 와이드·여백 많은 모던 톤, 텍스트 오버레이 공간 확보. 생성형 이미지 또는 Canvas/WebGL 인터랙티브도 가능.
2. **Philosophy / Narrative** — 1인칭 서사 + 비주얼:
   - 데이터/온톨로지 연결 시각화(사진·장소·일정·사람·지출 노드가 하나의 타임라인으로 연결되는 인터랙티브 그래프)
   - 원칙 카드: 왜 / 누구에게 / 무엇을 / 우선순위, "차별화는 무엇을 부각할지에서"
3. **Career (보조·컴팩트)** — 크레소티(재직 중)부터 모든 이력을 담백하게 표시하되 짧게. ★ 항목만 숫자로 부각(40분 완판·1억, 특허 2건, 10년 팀장, 공동창업, 20년 기록, 수석입학), 나머지는 한 줄 타임라인/접이식.
4. **Projects** — 각 카드: 의도 / 왜 / 누구에게 어떤 이익 (3줄 내외). Featured: 렛츠 캘린더, 컬처플로우, 렛츠 뷰. 라임리는 "시작 → 방치 → 렛츠 캘린더의 출발점" 흐름으로. 관계도(컬처플로우 허브, 라임리→캘린더) 시각화 권장.
5. **Footer / Contact** — GitHub 링크 + **'이메일 / Email' 버튼(mailto)**. 주소를 화면 텍스트로 노출하지 않음.
   - 가벼운 난독화: HTML에 원문 주소를 두지 않고 JS에서 조합. 예: `data-u="pyw213" data-d="naver.com"` → 클릭 시 `location.href = 'mailto:' + u + '@' + d`. (`aria-label="이메일 보내기 / Send email"`)

## 이중 언어 (Bilingual)
- **한국어 주, 영어 보조.** 섹션 타이틀·히어로·프로젝트 한 줄 요약에 영어를 작은 서브타이틀(작은 크기, 낮은 대비 아님 — WCAG AA 유지)로 병기. 본문 서사는 한국어 중심, 필요 시 짧은 영문 요약.
- `projects.js`에 `titleEn`은 이미 있음 → `summaryEn` 등 선택 필드로 확장.
- `<html lang="ko">` 유지, 영문 블록에는 `lang="en"`.
